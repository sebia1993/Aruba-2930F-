# SSH 수집 및 운영 안전

## 기본 원칙

이 도구의 장비 측 동작은 **읽기 전용 설정 수집**으로 제한합니다.

핵심 원칙:

- 설정 모드에 진입하지 않음
- 장비 구성을 변경하는 명령을 실행하지 않음
- 모델 확인 전에 `show running-config`를 실행하지 않음
- 모든 연결에서 `no page`를 먼저 적용
- SSH 장비 지문이 변경되면 자동 수용하지 않음
- 불완전한 출력은 정상 백업으로 저장하지 않음

## 명령 순서

```text
SSH 장비 지문 확인
→ 로그인/EXEC 프롬프트 확인
→ no page
→ show version
→ show modules
→ 2930F 식별
→ show running-config
→ 최종 프롬프트 및 출력 검증
```

### `no page`

ArubaOS-Switch CLI에서 설정 출력이 페이지 단위로 멈추는 문제를 방지하기 위해 매 연결과 재연결에서 먼저 적용합니다.

`no page` 명령 자체가 정상 완료되었는지 확인하지 못하면 이후 `show` 명령을 보내지 않습니다.

예외적으로 페이지 표시가 남는 경우 제한적으로 처리하지만, 출력 시간·크기·행 수 한도를 넘으면 수집 실패로 기록합니다.

현재 보호 한도:

- 최대 출력 크기: 20 MiB
- 최대 행 수: 250,000행
- 명령 시간 제한 적용

## EXEC 프롬프트

최초 연결과 Enable 전환 후 확인한 EXEC 프롬프트를 이후 명령 완료 판정에 재사용합니다.

다음과 같은 설정 모드 형태는 허용하지 않습니다.

```text
switch(config)#
switch(vlan-10)#
```

공백, 괄호형 표시 래퍼 또는 `+`가 들어간 정상 EXEC 프롬프트는 처리할 수 있지만, 복잡한 프롬프트에서 호스트명을 무리하게 추정하지 않습니다.

프롬프트에서 장비 이름을 확인할 수 없으면 정상 수집된 `running-config`의 유일한 최상위 `hostname`을 보완값으로 사용할 수 있습니다. 두 위치 모두에서 확인하지 못하면 백업 파일명은 IP를 사용합니다.

## 모델/SKU 식별

다음 두 결과를 함께 사용합니다.

```text
show version
show modules
```

판정 원칙:

- 공식 2930F SKU가 확인되면 해당 모델로 기록
- 명확한 SKU 없이 2930F 계열 증거만 있으면 2930F로 처리
- 여러 공식 SKU가 확인되는 정상 2930F VSF는 지원
- 모듈/트랜시버 부품 번호를 섀시 SKU로 오인하지 않음
- 다른 장비 계열 또는 상충하는 명시적 SKU가 있으면 수집 차단

## SSH 장비 지문

처음 보는 장비는 SSH 인증 전에 서버 공개 키의 SHA-256 지문을 운영자에게 보여줍니다.

승인된 지문은 다음 위치에 저장됩니다.

```text
%LOCALAPPDATA%\Aruba2930FConfigBackup\known_hosts.json
```

여기에 저장되는 것은 로그인용 개인 키가 아니라 **장비가 제시한 SSH 서버 공개 키의 지문**입니다.

이미 승인한 장비에서 지문이 바뀌면 다음 가능성을 확인해야 합니다.

- 장비 교체
- SSH 키 재생성
- OS 재설치/초기화
- 접속 대상 IP 변경
- 중간자 공격 가능성

운영 기록과 대조하기 전에는 새 지문을 임의 승인하지 않는 것을 권장합니다.

## 자격증명 처리

다음 값은 세션 전용입니다.

- 사용자 이름
- SSH 암호
- Enable 암호
- 장비 목록

암호와 Enable 암호는 설정 파일, `operation.jsonl`, 백업 TXT 메타데이터에 저장하지 않습니다.

설정 TXT 자체에는 실제 네트워크 구성이 들어 있으므로 별도 보호가 필요합니다.

## 레거시 SSH 알고리즘

일부 2930F는 다음과 같은 오래된 SSH 방식만 제공할 수 있습니다.

- `ssh-rsa`
- `diffie-hellman-group14-sha1`

현재 호환성 경로는 장비가 강한 알고리즘을 함께 지원하면 강한 방식을 우선하고, 필요한 장비에서만 레거시 방식이 협상되도록 구성되어 있습니다.

가능하면 장비의 ArubaOS-Switch 버전과 `show ip ssh` 결과를 확인하여 더 강한 알고리즘을 활성화하는 것이 좋습니다.

공통 알고리즘이 없으면 `SSH_ALGORITHM_INCOMPATIBLE`로 종료합니다.

Paramiko 4.0.0의 SHA-1 RSA 허용과 관련된 현재 예외는 [SECURITY.md](../SECURITY.md)에 기록되어 있습니다.

## 취소 동작

사용자가 취소하면:

- 새 장비 작업을 추가 배정하지 않음
- 열린 SSH 세션 종료 시도
- 이미 정상 완료된 백업은 보존
- 미완성 파일은 정상 결과로 취급하지 않음

## 현장 투입 전 권장 확인

1. 소수 테스트 장비에서 먼저 실행
2. 수동 `show running-config`와 백업 TXT 비교
3. 장비명과 모델/SKU가 정상 식별되는지 확인
4. `result.xlsx`의 성공/실패 집계 확인
5. SSH 장비 지문 검토 절차를 운영팀과 합의
6. 동시 접속 수를 낮게 시작한 뒤 수집 시간을 보고 확대
7. 백업 파일 보관 위치의 접근 권한 확인

실제 장비 검증 결과가 없는 상태에서 자동 테스트만으로 운영망 전체에 즉시 확대하는 것은 권장하지 않습니다.
