# Aruba 2930F 설정 백업 검증 보고서

이 문서는 자동 테스트와 실제 Aruba 2930F 장비 검증을 **서로 다른 증거 수준으로 구분**해 기록하기 위한 문서입니다.

운영망 정보가 포함될 수 있으므로 외부 공개본에는 실제 IP, 장비명, 계정, SSH 장비 지문, 설정 원문을 기록하지 않습니다.

## 1. 현재 검증 상태

| 구분 | 상태 | 근거 |
|---|---|---|
| 단위 테스트 | ✅ 완료 | GitHub Actions CI |
| 가상/루프백 SSH | ✅ 완료 | 로그인, 명령 처리, 레거시 SSH 경로 회귀 테스트 |
| Windows x64 패키지 | ✅ 완료 | PyInstaller 패키지 생성 및 실행 점검 |
| 릴리즈 무결성 | ✅ 완료 | SHA-256, BUILD_INFO, SBOM 검증 |
| 문서용 GUI 렌더링 | ✅ 완료 | 실제 `MainWindow`를 가상 데이터로 렌더링 |
| 실제 Aruba 2930F Standalone | ⬜ 미기록 | 아래 현장 검증 절차 수행 필요 |
| 실제 Aruba 2930F VSF | ⬜ 미기록 | VSF 환경이 있을 경우 별도 수행 |
| 다수 장비 장시간 실행 | ⬜ 미기록 | 현장 정책과 점검 창구에 따라 수행 |

> `미기록` 항목은 자동 테스트로 대체하거나 추정해 완료 처리하지 않습니다. 실제 허가된 장비에서 수행한 결과만 기록합니다.

## 2. 현장 검증 전 조건

실제 장비 검증은 다음 조건을 만족할 때만 수행합니다.

- 조직 정책상 자동 SSH 조회가 허용된 장비
- 설정 변경이 아닌 읽기 전용 점검이 허용된 계정
- 백업 파일을 안전하게 저장할 수 있는 점검 PC
- 장비 IP/호스트명/설정 원문을 외부 공개 자료에 포함하지 않을 수 있는 환경
- 테스트 중 문제 발생 시 즉시 중단할 수 있는 운영 절차

## 5. 수집 결과 대조 방법

실제 장비 검증에서는 프로그램 결과만 보고 성공으로 판정하지 않습니다.

### 5.1 설정 파일 완전성

1. 프로그램이 저장한 TXT 파일 확인
2. 동일 장비에서 허가된 수동 `show running-config` 결과와 주요 구간 대조
3. 시작/종료부와 장비 hostname 등 식별 가능한 구조 확인
4. 페이저 문자열이나 잘린 마지막 줄이 없는지 확인

### 5.2 장비 상태

검증 전후 다음을 확인합니다.

- 장비 재부팅 없음
- 설정 변경 없음
- 관리 접속 정상
- 운영 서비스에 이상 없음

이 프로그램은 설정 변경 명령을 사용하지 않지만, 실제 검증에서는 **읽기 전용이라는 설계 의도와 실제 동작이 일치하는지** 별도로 확인합니다.

- SSH 장비 지문
- running-config 원문
- VLAN, 서브넷, ACL 등 내부 구성 정보

## 8. 자동 검증과 현장 검증의 경계

자동 테스트는 다음을 강하게 보장하는 데 사용합니다.

- 입력/오류 처리 로직
- 명령 실행 순서
- 프롬프트와 페이저 처리
- 모델 식별 규칙
- 재시도 상태 전이
- 파일 저장과 보고서 생성
- 릴리즈 패키지 구조

반면 아래 항목은 실제 장비에서만 최종 확인할 수 있습니다.

- 특정 ArubaOS-Switch 버전의 실제 CLI 출력 차이
- 현장 SSH 정책과 암호화 알고리즘
- 특정 VSF 구성의 출력 형태
- 다수 장비를 대상으로 한 실제 네트워크 지연/타임아웃 특성

두 검증 수준을 혼합하지 않는 것이 이 프로젝트의 검증 원칙입니다.
