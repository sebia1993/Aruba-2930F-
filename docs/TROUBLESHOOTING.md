# 현장 문제 해결

## 권장 점검 순서

문제가 발생하면 프로그램을 반복 실행하기 전에 아래 순서로 확인합니다.

1. 어느 단계에서 실패했는지 확인
2. 오류 코드 확인
3. 동일 장비에 수동 SSH 접속 가능 여부 확인
4. 필요한 명령을 수동 실행해 출력 형식 확인
5. 네트워크 경로/ACL/AAA 문제와 프로그램 문제를 분리
6. 소수 장비에서 재현한 뒤 범위를 확대

## 연결 자체가 되지 않음

대표 오류:

- `TCP_TIMEOUT`
- `SSH_NEGOTIATION_FAILED`

확인 항목:

```text
PC → 대상 IP TCP 22 경로
방화벽/ACL
스위치 SSH 서비스
관리 VLAN/VRF
동시 접속 제한
장비 CPU 부하
```

Ping이 된다고 SSH가 반드시 가능한 것은 아닙니다. TCP 22 접근과 장비 SSH 서비스 상태를 별도로 확인합니다.

## 인증 실패

대표 오류:

```text
AUTH_FAILED
```

확인 항목:

- 사용자 이름/암호
- RADIUS/TACACS 등 AAA 정책
- 로컬 계정 사용 가능 여부
- 접속 위치에 따른 관리 접근 정책
- 계정 잠금 여부

인증 실패는 동일한 자격증명으로 반복해도 의미가 적으므로 기본 재시도 대상이 아닙니다.

## Enable 전환 실패

대표 오류:

```text
ENABLE_FAILED
```

장비가 Enable을 요구하는 환경인지 먼저 확인합니다.

수동 SSH에서 동일 계정으로 로그인한 뒤 필요한 권한으로 `show running-config`가 가능한지 확인합니다.

## SSH 장비 지문이 바뀜

대표 오류:

```text
HOST_KEY_CHANGED
```

즉시 새 지문을 승인하기 전에 확인합니다.

1. 실제 장비가 교체되었는가?
2. 장비 초기화나 SSH 키 재생성이 있었는가?
3. IP가 다른 장비에 재할당되었는가?
4. 운영자가 의도한 변경인가?

변경 근거가 확인된 뒤 기존 신뢰 정보를 갱신하는 것이 좋습니다.

## SSH 알고리즘 불일치

대표 오류:

```text
SSH_ALGORITHM_INCOMPATIBLE
```

일부 구형 2930F는 오래된 SSH 알고리즘만 제공할 수 있습니다.

장비에서 가능한 경우 다음을 확인합니다.

```text
show ip ssh
show version
```

가능하면 ArubaOS-Switch를 적절한 지원 버전으로 유지하고 SHA-2 기반 알고리즘을 사용할 수 있도록 설정합니다.

## `no page` 실패

대표 오류:

```text
PAGING_SETUP_FAILED
```

수동 SSH에서 다음을 확인합니다.

```text
no page
```

명령이 현재 사용자 권한에서 실행되는지, 실행 후 정상 EXEC 프롬프트로 돌아오는지 확인합니다.

이 단계가 실패하면 프로그램은 불완전한 `running-config`를 저장하지 않기 위해 이후 수집을 중단합니다.

## 모델 확인 실패

대표 오류:

```text
MODEL_UNSUPPORTED
```

수동으로 다음 결과를 확인합니다.

```text
show version
show modules
```

확인 포인트:

- 실제 장비가 2930F인가?
- VSF 구성인가?
- 섀시 SKU가 정상 출력되는가?
- 모듈/트랜시버 부품 번호만 보이는 상황인가?
- 출력 형식이 프로그램이 예상한 ArubaOS-Switch와 크게 다른가?

## 명령 시간 초과

대표 오류:

```text
COMMAND_TIMEOUT
```

가능성:

- 장비 CPU 부하
- SSH 세션 지연
- 비정상적으로 큰 출력
- 관리망 패킷 손실
- CLI 프로세스 응답 지연

한 장비만 반복적으로 느리다면 해당 장비의 운영 상태를 먼저 확인합니다.

## 백업 결과 대조

처음 현장에 투입할 때는 프로그램 결과를 바로 신뢰하기보다 수동 출력과 대조하는 것을 권장합니다.

예:

1. 프로그램으로 2~5대 백업
2. 같은 장비에 수동 SSH 접속
3. `no page`
4. `show running-config`
5. 저장 TXT의 시작/끝과 주요 설정 구간 비교
6. `result.xlsx` SHA-256 및 성공 상태 확인

## 대규모 장비 적용

처음부터 최대 동시 접속 수로 실행하지 않는 것이 좋습니다.

권장 방식:

```text
2~5대 기능 검증
→ 10대 동시 처리
→ 전체 수집 시간 확인
→ 필요 시 15~20대로 확대
```

장비 수보다 중요한 것은 관리망과 각 스위치가 동시에 SSH 세션을 처리할 수 있는지입니다.

## 공개 제보 시 주의

문제 해결을 위해 다음을 공개 저장소에 올리지 마십시오.

- 실제 장비 IP
- 사용자 이름/암호
- Enable 암호
- 전체 `running-config`
- 내부 VLAN/라우팅/ACL 정보
- 사내 호스트명 체계
- 민감한 SSH 장비 지문

가능하면 오류 코드, 진단 코드, 비식별화된 최소 출력만 사용하십시오.
